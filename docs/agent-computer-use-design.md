## 1. 已经验证的地基（2026-07-03）

- **模型自带视觉定位**：我们在用的 `MiniMax-M3` 原生支持 computer use，看截图输出**归一化 0–1000 坐标**（参照 1920×1080）。不换模型/端点/加钱。
- **API 形态**：MiniMax `/anthropic` 无专用 computer_use tool 类型，用**我们自定义 function + M3 填坐标**，完全可控。
- **坐标映射**：`agent/coords.py`（0–1000 ↔ 真实像素，多屏 region 偏移 + 越界钳制）。
- **精度实测**（2560×1440@100%）：大按钮/有高度的列表项 = 能点中；挨得极近的文字标签 = 会偏到隔壁。找不到目标时模型如实报 `found=false`，不瞎猜。
- **真点击闭环已跑通**：自然语言 →截图→ M3 定位 →换算像素→ 真单击 → 结果正确（探针 `agent/grounding_probe.py`）。
- **现成可复用**：截屏 `capture_screen`（排除蛋挞覆盖层）、安全闸（预演/确认/auto/急停）、语音确认、`AgentThread` 的 tool_use 多步循环、主线程 `RunController` 权威执行器。

## 2. 核心决策

### 2.1 一个助手全能（不分硬模式）

不设"配置模式 / 操作模式"的用户可见切换 —— 强制切模式对最不便操作 UI 的残障用户是负担。
**就一个助手**：改配置、用蛋挞能力操作、直接操作屏幕，工具全在，agent 按用户的话自己选。

> "互斥"退化为**内部优化**：若 prompt 撑不住，再按意图动态裁剪工具集；不做成用户能感知的模式。

### 2.2 分层执行器：优先用蛋挞自己的能力

agent 操作电脑时，按**可靠性从高到低**选路径，全部汇入同一条安全/执行管道：

| 层 | 手段 | 可靠性 | 状态 |
|---|---|---|---|
| **L1 语义** | 蛋挞已配的按钮/宏（`run_action`，标签语法） | 最高（用户亲手配、像素精确） | ✅ 已完成 |
| **L2 结构** | Windows UIAutomation 无障碍树（按控件名取真实矩形） | 高（桌面软件；Steam 等自绘程序支持差） | ⬜ 以后加 |
| **L3 坐标** | M3 视觉 grounding 出 0–1000 坐标兜底 | 中（能点任何东西；小目标需 refine） | 🚧 本次开发 |

**原则：配了的走 L1（精确、不用猜），没配的才 L3（坐标+确认兜底）。**
- "帮我按攻击" → 你配过攻击键 → L1 精确触发
- "帮我点开始游戏" → Steam 里没这绑定 → L3 坐标 + 确认

> 防返工：控制工具签名带"意图描述 + 坐标"，以后接 L2 UIA 时 schema 不变（内部先试控件名命中，失败退坐标）。

### 2.3 铁律：活是 agent 干，绝不把杂活甩回给用户

服务对象是残障用户 —— **让用户去找 exe 路径、报 appid、自己点，是方向完全反了**（用户能自己做就不需要 agent）。故：

- **绝不向用户索要技术细节**：文件/exe 路径、appid、窗口名、坐标等，一律 agent 自己截图看、自己找。
- **优先"看"而非"问"**：需要辨别时先 `capture_screen` 看；看完仍有歧义，才问一个最短的**选择题**，且只问**用户偏好/决策**（如"哪一款游戏"），绝不问技术手段。
- **一竿子做到底**：除非真被卡住或需用户拍板偏好，别停下来把活推回给用户。

### 2.4 打开东西：先分目标类型，用对策略

| 目标类型 | 正确策略 | 禁止 |
|---|---|---|
| **独立程序**（Steam/Chrome/微信） | 开始菜单搜名字（win→打名→回车，最通用免路径）；已配则 `app:名` | 让用户报路径 |
| **某 app 内的内容**（Steam 游戏 / 一首歌 / 网页 / 某设置） | **操作那个 app 的界面**：打开 app → 截图看 → 在界面里找到（可用 app 自带搜索）→ 点它 → 点开始/播放/打开 | 用 exe/路径启动、问用户要路径/appid |

> 教训（2026-07-03 实测）：模型曾试图用 exe 路径启动 Steam 里的游戏，找不到就问用户要 exe 路径 —— 典型的"甩活给用户"。根因是早期 prompt 把"app:/路径"当万能启动法，未区分"独立程序"与"app 内内容"。**app:/路径只适用于独立程序；app 内的内容必须靠看屏幕操作 UI。**

## 3. 多步任务执行模型

真实任务是多步的（开游戏 = 开 Steam → 选游戏 → 启动 → 进游戏点开始）。agent 要像人一样
**做一步 → 看一眼 → 再决定下一步**，不蒙头一口气执行。

### 3.1 计划优先，只确认一次整个任务

多步任务先让 agent **列出计划**给用户看，拿**一次总确认**，之后按计划执行，不逐步骚扰。

> 例：「我打算 ①打开 Steam ②找到 XX 点进去 ③点开始游戏 ④进游戏后点开始/继续。开始吗？」
> 用户确认一次 → 整个任务授权。

### 3.2 每步之间必"看一眼"

每个动作后 `capture_screen` 核对：上一步成了吗？据此决定下一步。**这是多步不翻车的核心。**
observation 也用于处理时序（程序刚开、游戏在加载）。

### 3.3 会等，但有上限

开程序、加载游戏有延迟 → **循环截图轮询**，直到看见期望状态；超时（如 30s）就停下问用户
"还在加载，继续等吗？"，不干等、不误判失败。

---

## 4. 分档确认（何时停下来问用户）

安全与不骚扰的平衡。逐次确认会累死多步任务；全自动又危险。故**在已授权的计划内分三档**：

| 档 | 触发条件 | 行为 |
|---|---|---|
| 🟢 **自动** | L1 蛋挞配好的按钮（用户亲手配、像素精确） | 直接做 |
| 🟡 **可见执行** | L3 坐标点击，且定位置信、目标符合计划 | 边做边告诉用户"正在点 XX"，可立刻喊停 |
| 🔴 **必确认** | ① 找不到目标(`found=false`) ② 定位拿不准 ③ 危险不可逆动作 | 停下，给标记图问用户 |

**🔴 危险动作判定**（强制确认，无视 auto）：关闭 / 删除 / 卸载 / 购买 / 支付 / 发送 / 提交 / 格式化 等关键词命中，或明显不可逆。

**全局开关**：
- `auto_execute`（已有）：用户信任后可把 🟡 也自动化；🔴 仍强制确认。
- **随时急停**（已有）：一个词/一个键中断整个任务。

**确认呈现**：🔴 确认弹窗展示**标记图**（红十字压在将点位置）+ 文案"要点这里吗？"，复用探针已有的画标记 + 现有 `ConfirmPopup` + 语音"确认/取消"。

## 5. 走查：开游戏（对照第 3、4 节）

| 步 | 动作 | 层 | 观察 | 确认档 |
|---|---|---|---|---|
| 0 | 列计划 | — | — | 🔴 一次总确认 |
| 1 | 开 Steam | L1（配了）/ L3（没配点任务栏） | 截图：起来没？没起→等 2s 再截 | 🟢 / 🟡 |
| 2 | 选 XX 游戏 | L3 坐标 | 截图：游戏页出来没？ | 🟡（找到）/ 🔴（没找到/拿不准） |
| 3 | 点绿色开始游戏 | L3 坐标 | 截图：开始启动没？ | 🟡（启动可逆、风险低） |
| 4 | 进游戏点开始/继续 | L3 坐标 | **循环截图等加载**，见主菜单再点；超时问用户 | 🟡 |

## 6. 要建的（都在现有地基上叠，不返工）

1. **控制工具集** `build_control_tools()`：`computer_click / move / double_click / type / key / scroll`，全吃 0–1000 坐标，带"意图描述"参数。归入 `EXEC_TOOLS`（走安全闸）。
2. **坐标执行路径**：主线程收到坐标动作 → `coords.norm_to_pixel` → `SetCursorPos` + 点击/输入。新增一条 marshal 通道（类比现有 `execute_requested`），或扩展它带类型。
3. **计划优先 + 分档确认**：改造 `AgentThread._exec_action` —— 现在"每次都确认"改为 🟢/🟡/🔴；任务级 plan 确认一次；system prompt 引导"先列计划、每步后 capture 核对"。
4. **会等**：加 `wait_ms` / 轮询能力（供开程序、加载游戏）。
5. **危险词判定**：一个纯函数，命中关键词 → 强制 🔴。
6. **工具装配**：一个助手把 配置集 + 控制集(L1+L3) + capture_screen 一起给到 agent（prompt 撑不住再动态裁剪）。

## 7. 上线前硬化（不阻塞本次，先记）

- **DPI 缩放**：截图像素 ↔ SetCursorPos 物理像素在 125%/150% 缩放下可能错位，需进程 DPI 感知 + 验证。（当前测试机 100% 无坑。）
- **多显示器**：探针只截主屏；正式功能要处理"点哪个屏"（`coords` 的 region 已支持偏移）。
- **`/anthropic` context 报 200K 非 1M**：长会话/多步 + 多张截图，需历史修剪 + 旧截图剔除（只留最近一两张图 block）。
- **精度增强 refine**：小目标"裁剪放大再定位一次"，把 🟡 命中率拉高（有 🔴 兜底，可缓）。
- **L2 UIA**：桌面软件精确点击，后续叠加。

## 8. 与设计哲学的对齐

- **帮助优先**：一个助手全能、优先用蛋挞已配能力、能操作任何软件。
- **知情透明**：计划先给你看、截图有告知、点击前给标记图、进度实时说。
- **始终可控**：分档确认、危险动作强制问、随时急停、auto 可调。
