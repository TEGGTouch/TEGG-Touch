# 运行中的快捷方案切换

编辑工具栏第一行的「＋ 方案切换」添加一个默认紫色的覆盖层按钮，宽度与底部「＋ 按键」入口一致。透明度和缩放改为标签、百分比在第一行，滑块在第二行。

双击按钮打开 960×700 的紧凑双栏编辑弹窗，关闭图标及外壳沿用普通按钮编辑器。左侧名称下方用一张触发表同时列出悬停、左键、右键、中键、侧键 1/2、滚轮上/下；每一行有独立的「固定／轮切」选项及方案标签，空字段表示不触发。点击字段后从右侧选择方案：固定模式替换单个目标，轮切模式按点击顺序加入多个方案且不重复。右侧方案采用两列排列，下方紧接当前字段的轮切列表，提供上移、下移和删除按钮。左侧标签的 × 或退格键也可移除方案；两栏独立滚动，标题和保存栏固定。

例如左键固定到 A、滚轮向上固定到 B、右键轮切 C → A 可以同时保存在同一个按钮中。轮切列表按设置顺序循环：当前方案在列表中时切换到下一个；不在列表中时从第一项开始。不同输入使用各自的列表。已删除的轮切方案在运行时会跳过；编辑保存时会提示移除失效目标。固定目标不可用时提示并保留当前方案。

设置悬停目标后才启用触发延迟和充能反馈，达到延迟只执行一次，必须离开按钮后再次移入才能触发。未设置悬停时延迟控件置灰，运行中无悬停充能或高亮，其他触发方式继续有效。没有悬停开关、释放延迟或连发。切换后的新按钮不会在鼠标仍留在原位置时再次悬停触发；鼠标长按也不会在新方案产生额外点击。

「设置 → 按钮配色」新增「快捷切换」一组，沿用基色取色、派生填充/描边/字色、预览和重置；默认基色为 `#A78BFA`。与其他按钮配色一样存入当前方案的 `button_colors.profile_switch`，切换方案时刷新。按钮的位置和各触发方式配置仍为所有方案共用，触发反馈色保留紫色。

紫色按钮由所有方案共用，存入本机 `settings/profile_switches.json`，独立于方案 JSON。复制按钮会生成新的身份；删除按钮会从所有方案中移除。原有方案导入、导出仍只包含方案本身。安装包构建继续排除本机设置。

切换通过运行控制器在当前输入帧结束后执行，保留运行模式、光标来源和运行定时器。加载前先校验目标文件，释放旧方案的悬停、点击、侧键、键盘映射和手柄状态，取消旧宏及其延迟动作，再加载新方案的场景、缩放、透明度、按键映射、语音配置和手柄需求。保留当前工具栏、穿透和显隐状态。旧语音识别结果和手柄延迟释放不能作用于新方案。目标场景加载失败会恢复原方案。

验证：`QT_QPA_PLATFORM=offscreen python -m unittest tests.test_profile_switch tests.test_ui_redesign tests.test_wheel_controls tests.test_adaptive_cursor`。运行切换测试使用临时方案目录、模拟物理输入及驱动，不向桌面注入按键。弹窗测试覆盖每行独立配置、固定目标替换、轮切去重与排序、清空、不保存退出、失效目标和含 + 的长方案名。还需在实际游戏中试用悬停轮切和鼠标点击。
